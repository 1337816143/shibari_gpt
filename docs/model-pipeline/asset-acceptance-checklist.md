# 3D 人物资产验收门槛

本清单用于决定一个人物资产是否可以从 `technical-review` 进入课程审核。通过浏览器成功显示，或看起来更接近真人，都不等于可以作为绳艺教学模型。

## 1. 来源与许可

- 必须保留原始来源页面、许可证页面、作者或机构署名。
- 禁止使用来源不明、许可证不允许再分发、仅限个人用途或无法确认授权链的模型。
- 远程模型必须显式设置 `allowRemote: true`；正式发布优先使用仓库内受控资产。
- 若资产经过重拓扑、换装、贴图重绘或骨骼修改，应记录修改者、日期、软件和导出版本。
- 文件进入仓库后记录 SHA-256，替换文件必须更新 `modelVersion`、校验值和审核记录。

## 2. 人物与视觉要求

- 明确呈现为成年人，不采用未成年人面部、比例或服装特征。
- 正式课程批准资产必须全身完整着装，不裸露，不使用色情化姿势、服装或镜头语言。技术候选目录可以保留成年、中性、非色情化的运动装腹部露出版本，但必须明确标注，且不得通过正式课程完整着装门禁。
- 身体比例、关节位置、手指和足部应足以支持教学观察。
- 服装应贴合但不误导人体结构；需要观察的解剖标志不能被夸张褶皱遮挡。
- 正面、背面、左右侧、顶部和课程局部特写均不得出现明显穿模、翻面、破损或贴图拉伸。
- 四视图与最终 GLB 必须来自同一模型版本，禁止用渲染图替代实际运行资产验收。

## 3. 几何与材质

- 单位、朝向和原点统一；站姿脚底应落在场景地面。
- 网格不得存在大面积非流形结构、重复面、破面或错误法线。
- 材质数量、纹理尺寸和透明材质数量应受控并记录。
- 不依赖未声明的外部纹理；正式 GLB 应能在断网环境完整加载。
- 半透明材质应检查排序、深度写入和移动端兼容性。
- CI 必须通过 GLB 2.0 容器、场景、节点、体积和 SHA-256 校验。

## 4. 骨骼、权重与语义映射

- 骨骼层级、命名和绑定姿势必须记录。
- 肩、肘、腕、髋、膝、踝和手指的旋转中心应接近实际关节。
- 权重不得在课程姿势中产生明显塌陷、拉丝、穿模或身体部位粘连。
- 每个课程姿势必须单独验收，不能只验证 T Pose 或 A Pose。
- 课程禁止的姿势漂移，应能通过骨骼约束或人工校验发现。
- 课程引用的每个 `anchorBone` 都必须在模型 `boneMap` 中登记。
- `boneMap` 中的每个实际骨骼名必须能在运行时 GLB 中解析。
- 更换骨骼、权重或 `boneMap` 后必须提高 `modelVersion`，旧模型审核自动失效。

建议至少登记以下稳定语义名，具体按课程需要增加：

- `pelvis`、`spine`、`chest`、`neck`、`head`；
- `leftUpperArm`、`leftForearm`、`leftHand`；
- `rightUpperArm`、`rightForearm`、`rightHand`；
- `leftThigh`、`leftShin`、`leftFoot`；
- `rightThigh`、`rightShin`、`rightFoot`。

## 5. 绳路教学适配

- 正式模型优先使用骨骼局部坐标，世界坐标仅保留给占位模型和不随姿势变化的场景元素。
- 接触点、安全检查点和风险区必须与可见人体位置一致。
- 绳索不得明显穿入身体，也不能因模型缩放而悬空。
- 在正面、背面、左右侧和局部特写中逐步检查每个绳段。
- 镜像模式下必须重新确认左右语义、活动绳头和提示文字。
- 模型隐藏、骨骼缺失或加载失败时，不得保留可能误导的悬空骨骼局部标记。
- 更换人物模型后，所有姿势、绳路、接触点与医学审核自动失效。

建议记录每步最大可见误差：

- 绳索与目标表面不应出现肉眼可见的大面积穿插；
- 接触标记中心应落在审核者确认的目标区域；
- 局部特写中绳路、文字和方向箭头不得互相遮挡关键位置。

## 6. 性能预算

当前交付层级预算：

- 移动优化候选不超过 12 MiB，嵌入贴图最大 1024；当前休闲装移动版约 11.6 MiB。
- 原始质量技术候选可以保留更大的文件和 2K–4K 贴图，但必须在选择器中显示实际体积、网络成本和技术审核状态。
- 当前运动装原始版上限 24 MiB；休闲装原始版上限 32 MiB。
- 原始质量候选不得被误标为移动优化资产，也不得因为可加载就自动成为正式课程默认资产。
- 后续可继续提供 LOD、Meshopt/Draco 或 KTX2 传输版本，但不得用压缩破坏骨骼权重、法线或教学可见性。
- 首次加载失败、超时、哈希不一致或 WebGL 不可用时，必须显示程序化模型或二维图，不得出现空白教学区域。
- Pixel 7 级移动配置应完成真实浏览器流程与内存观察。
- 3D 引擎、React Three、three-stdlib 和 GLB 解析器应保持分块加载。

## 7. 课程姿势测试矩阵

每个候选模型至少需要以下记录：

- 中立站姿；
- 双臂前伸和肘腕中立；
- 课程规定的最小与最大关节角度；
- 镜像状态；
- 模型透明度 50% 与 100%；
- 正、背、左、右、顶部与局部相机；
- 桌面高画质、标准画质与移动端低画质；
- 加载超时、错误哈希、缺失骨骼和 WebGL 失败回退。

## 8. 审核状态

- `placeholder`：仅工程占位，不允许作为正式课程证据。
- `technical-review`：许可和加载链路可验证，但尚未完成模型、姿势、绳路和安全审核。
- `approved`：仅表示模型资产通过技术与视觉验收，不等于课程内容已通过安全审核。

正式课程还必须具备与当前版本匹配的：

- `model-technical` 审核；
- `rope-technique` 审核；
- `medical-anatomy` 审核。

## 外部 QA 资产

仓库登记了 Khronos glTF Sample Assets 的 `RiggedFigure`，仅用于验证 GLB、蒙皮、动画、哈希和失败回退。该资产由 Cesium 提供，采用 CC BY 4.0；它不是本项目要求的成年女性正式教学人物，不会作为默认课程模型或最终视觉方案。


## 候选目录与正式批准的区别

- 候选目录的目标是让项目所有者比较外观、着装、体积和绳路可见性，因此可以同时保留多个技术版本。
- `technical-review` 表示来源、许可证、结构和加载链路可验证，不表示视觉、姿势、绳路或医学审核已经完成。
- 页面默认选择某个候选只是预览策略，不会修改课程数据中的正式 `modelAsset`。
- 只有 `neutral-fully-clothed` 资产才能进入正式课程 `approved` 门禁；运动装腹部露出候选可供比较，但不能绕过该规则。
