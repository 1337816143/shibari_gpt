# Phase 4：受控人物资产与候选目录管线

## 目标

本阶段将“浏览器能显示 GLB”升级为可生成、可选择、可审计、可失败和可回退的资产链路。技术候选可以公开比较，但不会自动获得正式课程批准。

## 浏览器加载顺序

1. 页面先展示模型目录和静态预览图；安全确认前不下载 Three.js 或人物 GLB。
2. 用户选择程序化人台、MPFB 移动版、两套 MPFB 原始质量版本或 Khronos QA。
3. GLB 通过 `fetch` 下载到内存；下载前后分别检查声明体积和实际体积。
4. 使用 Web Crypto 对完整 ArrayBuffer 执行 SHA-256 强校验。
5. 校验通过后创建临时 Blob URL，再交给 glTFLoader 解析。
6. 使用 SkeletonUtils 克隆骨骼场景，每个实例单独克隆材质。
7. 注册 `boneMap`，使教学叠加层可以使用骨骼局部坐标。
8. 显示网格、蒙皮网格、骨骼、三角面、材质、体积和包围盒诊断。
9. 下载、超时、完整性或解析失败时只替换人物为程序化人台；绳路和安全叠加层继续显示。
10. WebGL 整体失败时再降级到二维分步图。

## MPFB 候选目录

`tools/blender/run_candidate_pipeline.sh` 在一次联网作业中完成：

1. 下载 Blender 4.5 LTS 和官方 SHA-256；
2. 安装 MPFB；
3. 下载并安装 MakeHuman CC0 system assets；
4. 生成成年女性、game-engine rig、面部组件、头发、鞋履和运动装原始版；
5. 生成同一人物的休闲装原始版；
6. 从休闲装原始 GLB 二次导入，显式替换材质节点图像，并生成 1024 贴图移动版；
7. 为每套模型生成四视图、报告、许可证和 SHA-256；
8. 使用纯 Python GLB 审计器检查自包含贴图、网格、蒙皮、关节和每层预算；
9. 生成 `catalog-entry.json` 和总目录摘要；
10. 仅在常规 CI 通过后，由 GitHub Actions 将产物写回开发分支。

## 交付层级

### 休闲装移动版

- `neutral-fully-clothed`；
- 约 11.6 MiB；
- 最大贴图 1024；
- 默认网页技术候选；
- 硬门禁：不超过 12 MiB。

### 休闲装原始质量

- `neutral-fully-clothed`；
- 约 24.2 MiB；
- 最大贴图 4096；
- 保留用于材质和外观比较；
- 不因超出移动优先预算而删除，但页面明确提示首次下载成本。

### 运动装原始质量

- `neutral-sportswear-midriff`；
- 约 17.7 MiB；
- 最大贴图 2048；
- 短款运动上衣、长裤和鞋履，腹部露出；
- 按产品所有者要求保留，便于比较体型和绳路可见性；
- 不能作为 `approved` 课程的完整着装资产。

### Khronos 技术 QA

仅验证本地路径、CC BY 4.0、骨骼、蒙皮、动画、SHA-256、诊断和错误回退，不参与写实人物评价。

## 资产清单门禁

`scripts/verify-model-assets.mjs` 会交叉验证：

- 清单体积、实际文件体积和候选报告；
- SHA-256、`SHA256.txt` 和目录摘要；
- GLB 2.0 容器、场景、节点、网格和蒙皮；
- `boneMap` 的每个实际节点名称；
- 四视图预览；
- 来源、许可证和生成报告；
- 移动版 12 MiB 与 1024 贴图上限。

原始质量候选使用各自明确预算，而不是被移动预算错误拒绝。

## 不自动通过的事项

- “来自 CC0 生成器”不等于模型质量合格；
- “带骨骼”不等于课程姿势下的权重正确；
- “四视图没有明显问题”不等于所有关节角度都无穿模；
- “用户选择了某个模型”不等于课程 `modelAsset` 已批准；
- “模型资产 approved”也不等于课程 safety-review 或 approved。
