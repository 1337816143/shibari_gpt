# 项目完成状态

本文区分三种状态：工程实现、公开演示部署、正式教学发布。三者不能混为一谈。

## 1. 工程实现：完成

### 网站与学习流程

- 响应式首页、课程库、搜索和分类；
- 安全确认后才初始化 3D；
- 360° 视角、相机预设、镜像和画质控制；
- 播放、暂停、重播、时间轴、速度、循环和步骤跳转；
- 步骤目标、说明、张力、错误、检查、解除和完成清单；
- 本地收藏、完成记录和继续学习；
- 术语表、研究状态和审核透明度；
- WebGL 失败时二维降级。

### 3D 教学引擎

- 程序化完整着装成年人占位模型；
- GLB 加载、体积预算、超时和可选 SHA-256；
- 骨骼安全克隆、独立材质和动画选择；
- 网格、蒙皮网格、骨骼、三角面、材质和尺寸诊断；
- 模型级失败回退；
- Catmull-Rom 绳路渐进显示；
- 操作手、方向箭头、接触点、风险点和错误路径；
- 世界坐标和语义骨骼局部坐标；
- `boneMap` 与缺失骨骼显式错误。

### 数据、资产与发布治理

- Zod 课程、姿势、模型、步骤和审核 Schema；
- 本地模型资产清单；
- 来源、许可证、哈希和 GLB 容器静态校验；
- 版本绑定的模型、绳艺和医学审核；
- 课程批准状态不可绕过的运行时门禁；
- 模型验收清单和外部审核模板；
- 锁定依赖、只读 CI、浏览器测试和 Pages 自动发布；
- Blender 4.5 LTS + MPFB + CC0 MakeHuman 资产的可复现候选生成脚本。

## 2. 公开演示部署：完成并自动验收

公开地址：

`https://1337816143.github.io/shibari_gpt/`

发布链路为：

1. 开发分支运行 lint、严格类型检查、模型供应链校验、单元测试、生产构建和 Playwright E2E；
2. 只有 CI 成功后，默认分支上的生产 Pages 工作流才会启动；
3. 生产工作流使用该次 CI 的精确 `head_sha` 构建，避免分支继续移动造成“验收 A、部署 B”；
4. 构建产物写入 `deployment.json`，记录实际部署的源提交；
5. 部署后从公网校验提交指纹、首页、404 页面、JavaScript、CSS 和 QA GLB；
6. 公网 QA GLB 必须与仓库中的 SHA-256 清单一致。

生产部署入口保留在 `main`，应用代码仍位于 Draft PR 的开发分支，未合并到 `main`。

## 3. 生产写实人物：外部资产工作未完成

尚未将默认占位模型替换为最终写实人物。当前仍缺少一个同时满足以下条件的正式产物：

- 成年女性、中性、完整着装；
- 明确可再分发许可；
- 小于桌面 8 MB、移动端优先 5 MB；
- 合格拓扑、骨骼、权重和课程姿势；
- 完整四视图与真机验收；
- 与课程绳路、接触点、风险点和 `boneMap` 完整对齐。

仓库中的 MPFB 脚本已经定义生成方法，但脚本存在不等于正式模型已通过美术、绑定、压缩和真机验收。

已调研的现成候选：

- Khronos/Cesium RiggedFigure：仅用于技术 QA，不是目标人物；
- Three.js Michelle：示例媒体许可证链不够完整，不采用；
- Quaternius 女性角色：CC0、体积友好，但风格化低模，不符合最终写实要求；
- TalkingHead MPFB 女性 GLB：CC0 且更写实，但约 35 MB，超过默认课程预算，必须先压缩、LOD 和视觉验收。

## 4. 正式课程：外部独立审核未完成

示范课程仍为 `prototype-only`。正式教学发布需要真实专家完成：

- 绳艺技法审核；
- 医学/人体结构审核；
- 最终模型技术审核。

这些结论不能由开发者或自动化系统替代。审核记录必须绑定当前 `courseVersion` 或 `modelVersion`；版本变化后，旧批准自动失效。

## 5. 当前完成定义

本项目已达到“工程平台完成、公开演示可访问、发布链路可重复验收”的状态。

要把整个产品标记为正式教学完成，还必须由项目所有者提供或安排：

1. 合格的最终写实 GLB，或可联网的 Blender/MPFB 生产环境；
2. 模型美术、绑定、压缩、LOD 和移动端真机优化；
3. 独立绳艺、医学/人体结构和模型技术审核。

这些外部输入到位后，无需重写架构，只需登记资产、建立 `boneMap`、校准课程坐标、填写审核记录并通过既有门禁。
