# 项目完成状态

本文区分三种状态：工程实现完成、生产资产完成、正式课程完成。三者不能混为一谈。

## 1. 工程实现：完成

### 网站与学习流程

- 响应式首页、课程库、搜索和分类；
- 安全确认后才初始化 3D；
- 360°视角、相机预设、镜像和画质控制；
- 播放、暂停、重播、时间轴、速度、循环和步骤跳转；
- 步骤目标、说明、张力、错误、检查、解除和完成清单；
- 本地收藏、完成记录和继续学习；
- 术语表、研究状态和审核透明度；
- WebGL 失败时二维降级。

### 3D 教学引擎

- 程序化完整着装成年人占位模型；
- GLB 加载、体积预算、超时和可选 SHA-256；
- 骨骼安全克隆、独立材质和动画选择；
- 网格、蒙皮网格、骨骼、三角面、材质和尺寸诊断；
- 模型级失败回退；
- Catmull-Rom 绳路渐进显示；
- 操作手、方向箭头、接触点、风险点和错误路径；
- 世界坐标和语义骨骼局部坐标；
- `boneMap` 与缺失骨骼显式错误。

### 数据、资产与发布治理

- Zod 课程、姿势、模型、步骤和审核 Schema；
- 本地模型资产清单；
- 来源、许可证、哈希和 GLB 容器静态校验；
- 版本绑定的模型、绳艺和医学审核；
- 课程批准状态不可绕过的运行时门禁；
- 模型验收清单和外部审核模板；
- 锁定依赖、只读 CI、Pages 工作流和浏览器测试；
- Blender 4.5 LTS + MPFB + CC0 MakeHuman 资产的可复现候选生成脚本。

## 2. 生产写实人物：外部资产工作未完成

尚未将默认占位模型替换为最终写实人物，原因不是缺少加载能力，而是还没有一个同时满足以下条件的产物：

- 成年女性、中性、完整着装；
- 明确可再分发许可；
- 小于桌面 8 MB、移动端优先 5 MB；
- 合格拓扑、骨骼、权重和课程姿势；
- 完整四视图与真机验收；
- 与课程绳路、接触点、风险点和 `boneMap` 完整对齐。

仓库中的 MPFB 脚本已经定义生成方法。当前执行环境无法连接 MakeHuman 资产服务器，GitHub App 写操作也未稳定触发新 Actions，因此本轮没有伪造“已生成正式模型”的结论。

已调研的现成候选：

- Khronos RiggedFigure：适合技术 QA，不是目标人物；
- Three.js Michelle：示例媒体许可证链不够完整，不采用；
- Quaternius 女性角色：CC0、体积友好，但风格化低模，不符合最终写实要求；
- TalkingHead MPFB 女性 GLB：CC0 且更写实，但约 35 MB，超过默认课程预算，必须先压缩、LOD 和视觉验收。

## 3. 正式课程：外部独立审核未完成

示范课程仍为 `prototype-only`。正式发布需要真实专家完成：

- 绳艺技法审核；
- 医学/人体结构审核；
- 最终模型技术审核。

这些结论不能由开发者或自动化系统替代。审核记录必须绑定当前 `courseVersion` 或 `modelVersion`，版本变化后旧批准自动失效。

## 4. 部署

GitHub Pages 工作流已经配置，使用锁文件和 `npm ci`，开发分支与 `main` 均可构建。当前连接工具无法可靠读取 Pages 部署运行元数据，也无法独立确认公网地址，因此不把线上状态写成“已验证”。

## 5. 完成定义

在软件工程范围内，本项目已经具备继续接入正式人物和正式课程的完整平台能力。

要把整个产品标记为生产完成，还必须由项目所有者提供或安排：

1. 可联网的 Blender/MPFB 生成环境或合格正式 GLB；
2. 模型美术、绑定和移动端优化；
3. 独立绳艺、医学/人体结构和模型审核；
4. GitHub Pages 公网验收。

这些外部输入到位后，无需重写架构，只需登记资产、建立 `boneMap`、校准课程坐标、填写审核记录并通过既有门禁。
